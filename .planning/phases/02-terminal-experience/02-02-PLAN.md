# Plan 02-02: Terminal Width Auto-Fitting, CPU Row & Final Execution Report

## Context
This plan completes Phase 2 by equipping both live and final Gantt renderers with terminal width awareness, auto-scaling columns when workloads exceed terminal dimensions, adding a dedicated CPU row to visualize scheduling occupancy, and finalizing the report.

## Tasks

<task id="02-02-T1">
<description>
Implement terminal width detection and automatic horizontal scale compression.
</description>
<files>
engine-cpp/src/trace/trace_writer.cpp
</files>
<action>
1. Detect terminal width using `ioctl(fileno(f), TIOCGWINSZ, &w)`. If 0 or failed, fallback to 80 columns.
2. Calculate available timeline width (`W = term_width - 20`).
3. Compute scale factor `scale = 1; while ((total_ticks + scale - 1) / scale > W) scale++;`.
4. If `scale > 1`, print: `GANTT CHART (1 column = %d ticks)`.
</action>
<verify>
Workloads with >60 ticks compress columns automatically to fit 80 columns and announce compression factor.
</verify>
</task>

<task id="02-02-T2">
<description>
Add a dedicated CPU row to the Gantt chart in `trace_writer.cpp`.
</description>
<files>
engine-cpp/src/trace/trace_writer.cpp
</files>
<action>
1. In the Gantt chart rendering loop, after rendering rows for P1..PN, render a `CPU` row:
   `  CPU         │111111111111111111111111222333│`
   showing the task executing during each column (`P1` -> `1`, `P2` -> `2`, idle -> ` `).
2. Apply matching PID ANSI colors to the CPU row on TTY.
</action>
<verify>
Gantt chart in final report includes the `CPU` row clearly identifying the scheduled process at every tick.
</verify>
</task>

<task id="02-02-T3">
<description>
Validate final process table and summary metrics display in `write_live_report`.
</description>
<files>
engine-cpp/src/trace/trace_writer.cpp
</files>
<action>
1. Ensure process table prints:
   `P-ID`, `OS PID`, `burst`, `start`, `done`, `waiting`, `TAT`, `response`, `CPU ms`.
2. Format `CPU ms` from `p.cpu_ms` with 1 decimal precision, or `—` if not measured.
3. Print boxed summary: Avg Waiting Time, Avg Turnaround, Avg Response Time, CPU Utilization %, Throughput, Context Switches, Total Time.
</action>
<verify>
`scheduler_cpp --mode live --log` outputs complete process table with OS PIDs and CPU time on stderr.
</verify>
</task>
