# Plan 03-01: Process Group Isolation, PR_SET_PDEATHSIG, Signal Exit Codes & Guaranteed Cleanup

## Context
Phase 3 guarantees that no child process leaks under any termination pathway (normal completion, error, child crash, watchdog timeout, SIGINT, or SIGTERM). This plan implements PR_SET_PDEATHSIG across all worker backends, tracks the exact signal received to return standard exit codes (130 for SIGINT, 143 for SIGTERM), arms watchdog timeouts in pipe backend, and ensures `emit_cleanup()` runs on every exception and termination path.

## Tasks

<task id="03-01-T1">
<description>
Set PR_SET_PDEATHSIG and parent-alive check in pipe_backend and process_manager.
</description>
<files>
engine-cpp/src/process/pipe_backend.cpp
engine-cpp/src/process/process_manager.cpp
</files>
<action>
1. In `pipe_backend.cpp` child worker fork branch:
   - Call `::prctl(PR_SET_PDEATHSIG, SIGKILL);`.
   - Verify `if (::getppid() != parent_) ::_exit(1);`.
2. Do the same in `process_manager.cpp`.
</action>
<verify>
Child workers automatically die with SIGKILL if parent process is terminated ungracefully (`kill -9`).
</verify>
</task>

<task id="03-01-T2">
<description>
Track exact signal received to return exit code 130 (SIGINT) and 143 (SIGTERM).
</description>
<files>
engine-cpp/src/process/signal_backend.cpp
engine-cpp/src/scheduler/execution_controller.cpp
engine-cpp/src/main.cpp
</files>
<action>
1. Declare `volatile sig_atomic_t g_sig_received = 0;` in `signal_backend.cpp` and extern in `execution_controller.cpp` and `main.cpp`.
2. In signal handlers, record `g_sig_received = signum; g_stop_flag = 1;`.
3. In `main.cpp`, if `g_sig_received == SIGINT`, exit with 130; if `g_sig_received == SIGTERM`, exit with 143; otherwise `128 + g_sig_received`.
</action>
<verify>
Sending SIGINT results in exit 130; sending SIGTERM results in exit 143.
</verify>
</task>

<task id="03-01-T3">
<description>
Guarantee CLEANUP line emission on every exit and exception path.
</description>
<files>
engine-cpp/src/scheduler/execution_controller.cpp
</files>
<action>
1. In `execution_controller.cpp`, wrap the tick loop in a `try ... catch (...)` block.
2. In `catch (...)`, call `backend->abort_all()`, call `emit_cleanup(current_t)`, and rethrow.
3. Ensure `emit_cleanup` always logs the actual reaped count and 0 zombies.
</action>
<verify>
When an error or signal occurs mid-execution, a CLEANUP line is printed to stderr/NDJSON before process exits.
</verify>
</task>

## Verification
1. `bin/scheduler_cpp` killed with `kill -INT` exits 130 with a CLEANUP line.
2. `bin/scheduler_cpp` killed with `kill -TERM` exits 143 with a CLEANUP line.
3. Killing a child mid-run outputs an error and a CLEANUP line, exiting non-zero.
